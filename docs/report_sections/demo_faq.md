# 答辩 FAQ（模拟面试与简历诊断助手）

> 版本：v1（2026-10-23，阶段 5）｜用途：结题 / 答辩现场答疑口径
> 事实来源：`README.md`、`docs/decision_log.md`、`docs/api.md`、`docs/architecture.md`、`evaluation/README.md`、`prompts/*.md`、`frontend/README.md`。
> 口径原则：**只引用仓库已记录的事实，不虚构跑分**；目标值、进行中事项、临时模式均如实说明。

---

## 0. 一句话定位

面向高校学生的 AI 求职练习 Web 应用：简历诊断（A）→ JD 匹配（B）→ 模拟面试（C）→ 即时反馈报告（D）；**纯 Prompt 工程（不微调）**，`prompts/` 与 `evaluation/` 是核心资产，FastAPI + Vue 3 前后端分离，模型按模块独立路由（决策④）。

---

## 1. 为什么选择纯 Prompt 工程，不做微调？

- **成本与周期**：课程项目 12 周、无训练算力预算；微调的数据标注、训练与迭代成本不可控。
- **效果保障可替代**：用「结构化 Prompt + few-shot + JSON Schema 约束 + 评测集回归」替代微调兜底；质量波动通过 rubrics / 决策树 / 强制 grounding 等显式约束控制。
- **资产可迁移**：`prompts/` 与 `evaluation/` 全部纳入 git，提交历史即效果演化证据（结题报告直接引用）。
- **诚实边界**：不做微调意味着效果上限受所选模型能力约束；因此对评价指标（<3s 时延、偏差 ≤15% 等）只作为**目标值**，不宣称已达标。

## 2. 为什么每个模块用不同模型（决策④）？

- 四个模块任务性质不同：A 生成改写、B 结构化对齐、C 长对话流式、D 评分/复核；单一模型难以在所有任务上最优。
- 按任务选型：A `deepseek-chat`、B `glm-4-air`、C `glm-4-flash`（免费档撑长对话）、D 评分 `glm-4-plus`、D 复核 `deepseek-chat`（跨供应商、与评分不同模型，降低同源偏差）。
- 配置唯一事实来源 `backend/config/models.yaml`；业务代码只按路由名调用，换模型只改配置（仍须先跑评测回归）。
- 当前因用户指示临时全 DeepSeek 联调（见 Q3），但 `models.yaml` 与决策④设计未变。

## 3. 现在「临时全 DeepSeek 模式」怎么解释？和决策④矛盾吗？

- **来源**：2026-10-23 用户指示「暂时都使用 DEEPSEEK，等模型跑通，再混用两个模型」；新增 `backend/config/models.deepseek.yaml`，通过 `.env` 的 `MODELS_CONFIG_PATH` 临时启用。
- **临时映射**：A/D 评分 = `deepseek-v4-pro`（质量档）；B/C/D 复核 = `deepseek-flash`（速度档）；**评分与复核仍使用不同模型**，保留决策④「异模型」原则，但同供应商属临时状态。
- **不破坏设计**：`backend/config/models.yaml`（决策④）保持原样；删除 / 注释 `MODELS_CONFIG_PATH` 即恢复双供应商配置；恢复前须补 GLM Key 并按铁律跑真实评测回归。
- **结论口径**：临时模式只用于「先跑通真实链路」，不写入结题结论；真实 E2E 13/13 是在该模式下取得的。

## 4. 怎么保证评分客观、不「拍脑袋」？

- **4 维 rubric**：相关性 / 结构性 / 具体性 / 岗位匹配（各 1–10），`prompts/scoring.md` 给出每维定义与三档锚定示例（差 1–4 / 中 5–7 / 优 8–10，分带冻结）。
- **强制 grounding**：每个维度先引用候选人原文证据再给分；**证据少于 2 条该维度不得高于 6 分**，无信息 ≤4 分；代码层还有钳制兜底与测试（`backend/services/evaluation.py`）。
- **低温 + 结构校验**：评分温度固定 0.1（`models.yaml`）；输出按 `InterviewEvaluation` Pydantic Schema 校验，失败自动修复重试，仍失败降级。
- **交叉复核**：换一个模型（不同供应商 / 不同模型）逐维复核，输出认可/调整与偏差说明（单维调整幅度有上限）。

## 5. 「人工与 AI 评分偏差 ≤15%」有实测数据吗？

- 这是**阶段 4 目标值**，不是已完成结论。评分一致性抽样（10 条 golden QA、比较 overall 与人工标注中心分、相对偏差 ≤15%）已在阶段 4 收尾任务中落地：脚本与报告以 `evaluation/reports/consistency.md` 为准（若现场查看时该文件尚未生成，说明仍在进行中）。
- 已有的相关证据：全部评分逻辑有 mock 单测；真实 E2E 中报告链路产出了合法的 4 维评分与交叉复核结果。
- 口径：**不宣称「已达标 / 偏差 15%」**，只说明验证方法与当前进度。

## 6. 评测集和「改 Prompt → 跑评测 → 对比 → 提交/回滚」铁律怎么落地？

- `evaluation/README.md` 是样本格式唯一事实来源（`schema_version=1` 已冻结）：QA 样本含 poor/medium/good 三档锚定答案与人工分带，简历样本含人工标注问题清单。
- `run_eval.py` 对比 v_old（`prompt_baselines/scoring_v1.md`）与 v_new（当前 Prompt），指标为 `band_hit_rate`（主）、`MAE`（主）、`mean_score`；**分数下降 → 非零退出码（1）**，可接 git hook / CI 强制拦截；数据错误退出码 2。
- mock 模式无 Key 也能演示「改 Prompt → 评测 → 对比 → 拦截」闭环（`--mock-scenario regress`）；real 模式需有效 Key。
- 当前规模：金标准第一批 **8 份简历 + 20 条 QA**（实习/秋招/保研分布），阶段 4 扩至目标 **20 份 / 30 条**。

## 7. Prompt v2 的真实评测回归做了吗？为什么说「临时口径」？

- **已做**：全部 Prompt v2（A/B/C/D + 三场景）与 mock 回归；全仓 mock 测试 **301 passed + 1 skipped + 80 subtests**。
- **未完成**：真实 `run_eval.py --real` 的 v1 vs v2 对比。原因：临时全 DeepSeek 模式下 v_old（按 GLM 调优的历史 v1 基线）在 `deepseek-v4-pro` 下无法产出合法 `InterviewEvaluation` JSON，回归在 v_old 阶段中止，属「临时模型 / 基线不匹配」而非 v2 变差。
- **处置**：v2 维持「临时提交」口径（真实回归前不继续叠加效果优化）；待 GLM Key 到位、恢复决策④配置后按铁律重跑全量真实回归，分数不降保留 v2、下降回滚。

## 8. 30 分钟长面试怎么保证不中断、不爆 token？

- `context_manager`：维护 messages 数组 + 滑动窗口（保留最近 N 轮完整对话）+ token 估算（tiktoken，失败降级字符估算）。
- **双触发压缩**：C 模块每 **5 轮**触发滚动摘要；接近上下文窗口 **90%** 阈值自动摘要压缩（保留岗位/简历关键信息、已问问题、候选人关键回答，而非简单截断）。
- **兜底结束**：token 占用 ≥95% 时优雅结束（`finish_reason=token_limit`），会话状态与转录完整保留供报告使用；单方向追问 ≥2 次强制换向，避免无限追问。
- 前端 SSE 逐字渲染 + 停止生成；长对话成本主要落在免费档 / 速度档模型上。

## 9. 追问决策树怎么保证「会追问、追问自然」而不是模板化？

- `prompts/interviewer/system_base.md` 把 D1–D5 写成**显式四元组**：触发条件 / 判定信号 / 追问动作 / 目的，并规定判定优先级（先 D5 换向保护，再 D1→D3→D2→D4）。
- **代码侧判定规则**：`interview_agent.py` 根据回答信号（含糊 / 技术名词 / JD 冲突 / 优秀）决定本轮 `rule_id`，再注入 Prompt；**模型只负责措辞**——规则稳定、可单测，避免长对话中规则漂移。
- 角色卡用 `{{company}}/{{role}}/{{style}}/{{scene}}` 注入人设；few-shot 示范「一次一问 + 含糊→追数据来源」的节奏；禁止事项（一次多问 / 脱离简历凭空提问 / 自我修正评分）写进 Prompt。
- 实测证据：真实联调一轮 SSE 返回 `rule_id=D2`、`follow_up_depth=1`，与决策树一致。

## 10. 三场景（实习 / 秋招 / 保研）差异体现在哪？切换要改代码吗？

- 三个场景变体文件 `prompts/interviewer/scene_intern.md` / `scene_autumn.md` / `scene_grad.md`：只写**语气与问题侧重差异**，不重复 base 决策树（实习轻松鼓励、秋招正式适度压力、保研学术严谨）。
- 接口 `POST /api/interview/sessions` 的 `scene` 三选一（默认 `intern`），前端面试页场景选择器切换即可；**无需改代码**，模型配置 / 业务逻辑不变。
- 三个场景均已在契约（`docs/api.md`）与实现中支持（E2E 主链路以 `intern` 场景完成 13/13 验收；秋招 / 保研由同一接口 `scene` 参数与场景 Prompt 变体承载）。

## 11. 隐私与安全：简历、Key、数据怎么处理？

- **本地解析优先**：PDF/DOCX 在本地解析成文本，不直接上传原始文件；解析失败/扫描件提示改用「粘贴文本」。
- **上云前脱敏**：`backend/utils/mask.py` 对姓名、电话、邮箱脱敏后再调用云端模型。
- **Key 管理**：只从环境变量 / 根 `.env` 读取（`.gitignore` 保护，不进 git）；前端不保存、不请求任何 Key；已用 `git log -S` 核验无 Key 进入提交历史；`deploy_check.py` 只报「是否配置」，绝不打印值。
- **素材合规**：仓库内简历 / JD / 面试对话**全部为 LLM 生成的虚构数据**，不含真实个人信息；演示素材见 `data/demo/`，该目录 README 明确「虚构、脱敏」。

## 12. 项目的创新点 / 技术亮点是什么？

1. **把 Prompt 当代码管**：版本注释 + 评测集 + `run_eval.py` 强制回归关卡（分数下降非零退出），无微调路线下的质量闭环。
2. **追问决策树显式化 + 代码侧规则注入**：D1–D5 可维护、可测试；模型只措辞，长对话规则不漂移。
3. **可解释评分**：4 维 rubric + 三档锚定 + 强制先引用原文证据（证据不足降分）+ 跨模型交叉复核。
4. **工程兜底完整**：模块级模型路由（重试/超时/流式/错误码）、JSON Schema 校验与修复重试、上下文摘要压缩、统一响应壳与契约冻结。
5. **可演示性强**：Mock 与真实后端双实现同构、一键切换；FastAPI 单进程托管前端 + SSE 真实流式；真实 E2E 13/13 验收。

## 13. 当前局限与下一步计划？

- **临时全 DeepSeek 模式**：需补 GLM Key 恢复决策④双供应商，并按铁律重跑真实评测回归。
- **Prompt 真实回归未完成**：v2 仍为临时口径（Q7）。
- **评测集规模有限**：当前 8 份简历 / 20 条 QA，阶段 4 扩至 20 / 30；评分一致性抽样与模型分配 A/B 在阶段 4 收尾落地。
- **实现边界**：会话与报告存储在后端进程内存（重启即失，报告最近 200 份），未接数据库；历史仅前端 localStorage；未做语音 / 桌面端 / 小程序（按清单裁剪）。
- **下一步**：恢复双供应商与真实回归 → 评测集扩量 → 部署打包与演示材料 → 试用反馈迭代。

## 14. 为什么用 SSE 而不是 WebSocket？为什么推荐单进程演示？

- **SSE 足够且更简单**：面试对话是服务端 → 客户端的单向增量文本，SSE 基于普通 HTTP（`text/event-stream`），浏览器 `fetch + ReadableStream` 即可解析，无需额外协议升级与心跳管理；契约冻结为 `{"event":"delta|done|error"}` 信封，mock / real 同构。
- **单进程演示是部署形态，不是架构**：`backend/main.py` 在 `frontend/dist` 存在时托管 SPA 与静态资源，一条 uvicorn 命令同时提供页面与 `/api`，同源无跨域、现场稳定；开发与交付仍可前后端分离（Vite dev server + uvicorn），契约不变（`docs/api.md` 15 条接口）。

## 15. 现场如果模型超时 / 网络抖动 / 没有 Key 怎么办？

- **演示前自检**：`scripts/deploy_check.py` 检查依赖、`frontend/dist`、`.env`、5 组 Key 是否配置（不显示值）、模型路由 5 条与评分/复核异模型；`scripts/e2e_real.py` 可提前真实验收 13/13。
- **现场兜底**：报告用预生成 `report_id` 直接拉取（只读、不耗调用）；面试失败可展示 `data/demo/transcripts/interview_demo_01.json`（历史对话 + 评分 + 复核）讲结构；仍不可用则切 Mock 构建产物演示交互，并**明确说明当前为 Mock 模式**。
- **口径**：网络与额度不可控属客观风险；真实链路已在 2026-10-23 完成 E2E 13/13 验收，现场不作「必须全绿」的过度承诺。
