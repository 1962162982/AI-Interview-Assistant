# 现场 Demo 脚本（真实模式 · 单进程演示）

> 版本：**v2（2026-10-23，阶段 5）** ｜ 适用：答辩 / 结题现场演示
> 目标：用 **3 分钟精简版** 或 **8 分钟完整版** 演示「A 简历诊断 → B JD 匹配 → C 模拟面试 → D 反馈报告」全链路。
> 形态：**真实模式**（前端 `VITE_USE_MOCK=false`，调用真实 FastAPI `/api`）+ **单进程托管**（FastAPI 同时托管 `frontend/dist` 页面与 API，一条 `uvicorn` 命令，无需另起静态服务器）。
> 当前模型状态：**临时全 DeepSeek 联调模式**（用户指示，见 `docs/decision_log.md` 2026-10-23）；决策④双供应商配置 `backend/config/models.yaml` 未改动，删除 `.env` 中 `MODELS_CONFIG_PATH` 即可恢复。
> 实测参考（2026-10-23，临时全 DeepSeek）：`scripts/e2e_real.py --with-report` **13/13 步通过、约 5.6 min**；前端联调建会话 2.6s、SSE 一轮 20 个 `delta` + 1 个 `done`；真实耗时随模型 / 网络波动，以下时间均为参考值。
> 相关文件：`scripts/run_demo.ps1`（一键启动）、`scripts/deploy_check.py`（部署自检）、`docs/deployment.md`（部署手册）、`docs/api.md`（契约冻结 v1，15 条接口）、`data/demo/`（冷启动素材）。

## 一、演示前准备（前 10 分钟）

### 1. 后端环境与 Key（Key 只放本机 `.env`，绝不投屏 / 截图 / 贴聊天）

```powershell
cd AI-Interview-Assistant

# 1) 虚拟环境与依赖（已有 .venv 则跳过）
.\.venv\Scripts\python.exe -c "import fastapi, uvicorn, openai, yaml, tiktoken"   # 无输出即 OK

# 2) 根目录 .env 已就绪（不存在则复制模板并填写，.env 不进 git）
#    Copy-Item .env.example .env
#    当前阶段：.env 中 5 组模块 Key / Base URL 均指向 DeepSeek，
#    并设置 MODELS_CONFIG_PATH=backend/config/models.deepseek.yaml（临时全 DeepSeek 模式）
```

> **口径**：现场只说明「当前按用户指示临时全部使用 DeepSeek 跑通链路，决策④的每模块独立模型设计不变」，**不展示 Key / `.env` 内容**。

### 2. 前端构建产物（必须是“真实模式”构建；无 Node 的演示机需提前拷贝 `frontend/dist`）

```powershell
cd frontend
# 真实模式构建配置（frontend/.env，gitignored）：
#   VITE_USE_MOCK=false
#   VITE_API_BASE_URL=http://127.0.0.1:8000
pnpm build          # 有 Node（>= 20.19）时；产物 frontend/dist/
cd ..
```

- **无 Node 的演示机**：在有 Node 的开发机按上述配置构建后，把整个 `frontend/dist/` 随项目拷到演示机；演示机用 `run_demo.ps1 -SkipBuild` 或手动 uvicorn（见 `docs/deployment.md` §五）。
- **判断构建模式**：打开首页，右上角 chip 显示「**真实后端模式**」才正确；若显示「Mock 数据模式」，说明 `dist` 是 mock 模式旧构建，需删除 `frontend/dist` 后按上述配置重建（或演示前替换为真实模式 dist）。
- 当前工作区已有 2026-10-23 构建的 `frontend/dist`（含 JD 匹配雷达图加分项）；**`dist` 已被 `.gitignore` 忽略**，交付 / 演示机需按上述方式预置（构建或拷贝）。

### 3. 一键自检（演示前必跑，输出为 PASS / WARN / FAIL，含 FAIL 时退出码 1）

```powershell
.\.venv\Scripts\python.exe scripts\deploy_check.py
# 预期：Python / 依赖 / dist / .env / 5 组 Key 已配置（只报有无，不显示值）/ 模型路由 5 条 /
#       决策④“评分与复核异模型”均 PASS；临时 MODELS_CONFIG_PATH 会以 WARN 提示（正常）
```

### 4. 冷启动预跑（强烈建议，避免现场从零生成）

1. 启动服务（见第二节），浏览器打开 `http://127.0.0.1:8000/`；
2. **完整跑一遍**：填入示例简历 → 诊断 → 填入示例 JD → 匹配 → 开始面试 + 1 轮回答 → 结束面试 → 生成报告；
3. 把生成的 `session_id` / `report_id` 记在便签（不投屏）；
4. **演示全程不要重启后端**：会话与报告当前存于**后端进程内存**（报告保留最近 200 份），重启后按 ID 查询会返回 `3001`；
5. 浏览器 `localStorage` 会保存最近简历 / 会话 / 报告，报告页可直接带参打开展示：
   - 预生成报告：`http://127.0.0.1:8000/report?report=<report_id>`
   - 用已有会话生成报告：`http://127.0.0.1:8000/report?session=<session_id>`（真实模式需手动点「生成报告」）。

## 二、启动（单进程，推荐）

### 方式 A：一键脚本（Windows / PowerShell 7）

```powershell
cd AI-Interview-Assistant
pwsh -NoProfile -File scripts/run_demo.ps1            # 默认 http://127.0.0.1:8000
# 快速启动（已有 dist）：pwsh -NoProfile -File scripts/run_demo.ps1 -SkipBuild
# 换端口：             pwsh -NoProfile -File scripts/run_demo.ps1 -Port 8080 -SkipBuild
```

脚本行为：检查 `.venv` 与后端依赖 → `frontend/dist` 缺失时构建（DSH 环境用自带 Node/pnpm；普通演示机请提前构建）→ 检查 `.env` 是否存在（不读取内容）→ 检查端口 → 启动 uvicorn 并打印页面地址 / 接口文档 / 健康检查地址。

### 方式 B：手动单进程

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### 启动成功判定

| 检查 | 地址 | 预期 |
| --- | --- | --- |
| 页面 | `http://127.0.0.1:8000/` | 打开首页，chip 显示「真实后端模式」 |
| 健康检查 | `http://127.0.0.1:8000/health` | `{"status":"ok"}` |

## 三、五页逐步操作与预期输出（真实模式）

### ① 首页 `/`（约 30 秒）

**操作**：打开 `http://127.0.0.1:8000/` → 指出顶部 chips 与模型路由表 → 点「检测后端」→ 指出本地历史面板。

**预期输出**

- chips：四层架构 / 每模块独立模型 / **真实后端模式**；
- 「模块 → 模型路由」表 **5 行**（来自 `GET /api/meta/routes`）。**当前临时全 DeepSeek 模式**显示：`resume_diagnosis`、`evaluation` = `deepseek-v4-pro`；`jd_matching`、`interview_agent`、`cross_review` = `deepseek-flash`；温度 / 流式 / 超时 / 重试一并展示；
- 「检测后端」→ **「后端在线（GET /health 正常）」**；
- 本地历史：最近简历（来源 / 字数）、最近会话 `session_id`、最近报告 `report_id`。

**讲解要点**：4 模块 5 页面对应四层架构；纯 Prompt 工程不微调；决策④「每模块独立模型 + 评分与复核异模型」，模型细节全收口在配置；**当前临时全 DeepSeek 是用户指示的联调模式，不是决策变更**。

### ② 简历诊断 `/resume`（约 60–90 秒）

**操作**：进入「简历诊断」→ 点「**填入示例简历**」（等价素材：`data/demo/resumes/resume_demo_01_intern.md`；也可上传 `.docx` 或粘贴文本）→ 目标岗位默认「后端开发实习生」→ 点「**开始诊断**」→ 等待时讲 5 项检查清单。

**预期输出**

- 按钮显示「诊断中…」，可点「取消请求」；
- 完成后展示：**整体 summary + 问题清单 + 亮点**；每条问题包含 `check_item`（量化表达 / 动词弱化 / 关键词对齐 / 结构问题 / 错别字格式）、`priority`（高 / 中 / 低）、**逐字原文引用**、问题说明、**改写示例**；
- 成功提示：「诊断完成；结果已保存为本地历史，可在 JD 匹配 / 模拟面试中复用。」。
- 参考耗时：诊断请求 = 1 次模型调用（JSON 校验失败时路由器自动修复重试），实测 v4-pro 单次诊断约 **76s**，现场按 **30–90s** 预期。

**讲解要点**：检查清单式 + few-shot 改写；**强制引用原文**（原文引用是证据链起点）；结构化 `ResumeStructured` 是 B / C / D 的公共依赖；失败有降级（解析失败 → 改用粘贴文本）。

### ③ JD 匹配 `/jd`（约 40–60 秒）

**操作**：进入「JD 匹配」→ 顶部确认简历来源为「本地历史简历（…）」（没有则点「使用示例简历」）→ 点「**填入示例 JD**」（素材：`data/demo/jds/jd_demo_backend_intern.md`）→ 点「**开始匹配**」。

**预期输出**

- 按钮显示「匹配中…」，可取消；
- 完成后展示：**匹配度 0–100**、**能力项列表**（已覆盖 / 部分覆盖 / 缺失 + 简历证据 + 说明）、**差距清单**（能力项 / 差距 / 补齐建议）、**能力雷达图**（SVG，无第三方图表库，加分项）；
- 提示：「匹配完成：匹配度与差距清单仅供参考，建议结合人工判断。」。
- 参考耗时：文本路径下内部含简历结构化 + 两段式匹配（约 3 次调用；传结构化简历时为 2 次），约 **30–120s**。

**讲解要点**：**两段式调用**——第一步 JD → 能力项 JSON（低温 0.2），第二步简历 × JD 逐项对齐评分 + 差距清单；拆开可分别评测、降低遗漏；status 三态可解释。

### ④ 模拟面试 `/interview`（约 60–120 秒 / 完整版可 2 轮）

**操作**：进入「模拟面试」→ 场景选「**实习**」（可顺带展示秋招 / 保研选项与语气差异）→ 点「**开始面试**」→ 首问出现后，在回答框输入一段**含糊回答**（示例：「就是把数据库查询优化了一下，加了个索引。」）→ 点「**发送回答**」→ 观察逐字流式追问 →（可选）再发一条更具体的回答 → 点「**结束面试并生成报告**」。

**预期输出**

- 「会话已创建：`sess_…`（已记录到本地历史）」；
- 面试官气泡 **SSE 逐字输出**（`delta` 增量 → `done` 更新题目 / 状态）；按钮显示「面试官输入中…」，可「停止生成」；
- 右侧「会话状态」：当前题目 `qN`、**追问深度**、已进行轮数、**上下文占用 %**、`rule_id` / `direction`；
- 含糊回答命中 **D1（追问数据来源）**，如「优化前后 QPS 是多少、3 倍怎么测出来的」；继续回答技术细节可命中 D2（深挖原理）；同方向追问 ≥2 次会强制换向（D5）；
- 结束面试后跳转 `/report?session=<session_id>`。
- 参考耗时：首问约 **2–5s**；每轮 SSE 问答约 **3–10s**（实测首问 2.6s、一轮 20 个 delta）。

**讲解要点**：角色卡 + 显式追问决策树 **D1–D5**；**代码侧先判定 `rule_id` 再注入 Prompt，模型只负责措辞**（规则稳定、可测试）；三场景（实习 / 秋招 / 保研）语气与问题侧重不同；上下文管理器每 5 轮滚动摘要 + 90% 窗口阈值压缩，保证长面试不中断。

### ⑤ 反馈报告 `/report`（约 30–120 秒；3 分钟版建议用预生成报告）

**操作（二选一）**

- **现场生成**：面试结束后页面已带 `session` 参数，点「**生成报告**」（页面提示：评分 + 交叉复核 2 次模型调用，约 30–90 秒；实际为逐题评分 + 1 次复核，随轮数增加；真实 v4-pro 可能更久，可「取消请求」）；
- **预生成展示（3 分钟版推荐）**：直接打开 `http://127.0.0.1:8000/report?report=<report_id>`（只读、不耗调用）。

**预期输出**

- 4 个维度卡：**相关性 / 结构性 / 具体性 / 岗位匹配**（各 1–10 分），每维下方列出**原文证据**；
- **亮点 / 短板 / 改进建议** 三栏；
- **交叉复核**：复核模型结论（认可或有调整建议）+ 偏差说明（与评分模型不同）；
- 报告摘要 + 「**下载 Markdown**」按钮（现场可导出，文件名 `report_<report_id>.md`）。
- 参考耗时：逐题评分（每题 1 次）+ 交叉复核（1 次）；2 轮对话约 3 次调用，页面提示约 30–90s，实际随轮数与模型波动（实测 cross_review 约 16s，评分 v4-pro 较慢）。

**讲解要点**：4 维 rubric + 三档锚定 + **强制先引用证据再给分**（证据不足 2 条该维不得高于 6 分）+ 评分温度 0.1 + **跨模型交叉复核**；报告可追溯、可导出；报告存后端进程内存（重启后 3001）。

## 七、常见失败提示与处置

| 现象 | 可能原因 | 现场处置 |
| --- | --- | --- |
| 首页 chip 显示「Mock 数据模式」 | `frontend/dist` 为 mock 模式构建 | 删除 `frontend/dist`，按真实模式配置重新 `pnpm build`；或用预置的真实模式 dist 替换 |
| 页面 404 / 白屏 | 后端未启动 / `frontend/dist` 缺失 / URL 端口不对 | 看启动终端是否打印页面地址；确认 `frontend/dist/index.html` 存在；仅 API 模式时页面会 404 |
| 路由表一直加载 / 请求失败 | 后端未就绪 / 前端 `VITE_API_BASE_URL` 指向错误端口 | 同源单进程一般无跨域；确认构建时 `VITE_API_BASE_URL=http://127.0.0.1:8000`；刷新重试 |
| 接口返回 `code=2001` | Key 未配置 / 鉴权失败 / 超时 / 限流 | 跑 `scripts/deploy_check.py` 定位缺失项（只报有无）；重试一次；仍失败按冷启动预案降级并说明 |
| 接口返回 `code=2002` | 模型输出 JSON 校验失败（修复重试后） | 重新提交；连续失败切预生成报告 / Mock 展示 |
| 接口返回 `code=3001` | 会话 / 报告不存在（重启或过期） | 重新创建会话 / 重新生成报告；确认前后端同一后端进程 |
| 接口返回 `code=1002` | PDF 损坏 / 扫描件 / 格式不支持 | 改用 `.docx` 或「粘贴文本」通道 |
| 报告生成超过 1 分钟 | 评分模型（v4-pro）响应慢 | 页面可「取消请求」；改用预生成报告；不要刷新页面 |
| SSE 卡住 / 中断 | 网络抖动 / 超时（前端 180s 上限） | 点「停止生成」后重新发送；必要时刷新并重新开始面试 |
| 端口被占用 | 8000 已被其他进程占用 | `run_demo.ps1 -Port 8080` 或 uvicorn `--port 8080` |
| 无 Node 机器 | 无法现场构建 `dist` | 提前在有 Node 机器构建后整体拷贝 `frontend/dist`；演示机用 `-SkipBuild`（见 `docs/deployment.md` §五） |
| 控制台中文乱码 | Windows GBK 控制台 | 以浏览器页面展示为主；脚本 / 服务输出为 UTF-8 兼容处理，不影响功能 |
